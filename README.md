# Portfolio

Personal portfolio site — projects, case studies, journal, resume.
Astro 5, fully static, deployed to GitHub Pages at **https://anishgiri.dev**.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Local dev server on `:4321`. Journal drafts are visible here. |
| `npm run check` | Content cross-reference checks, then `astro check` (types). The gate CI runs. |
| `npm run check:content` | Just the cross-reference checks — fast. |
| `npm run build` | Validates all content against the Zod schemas and writes `dist/`. |
| `npm run preview` | Serve `dist/` locally. |

There is no test suite. Three things catch breakage, and they catch different things:

- **`astro check`** is the only typecheck. `astro build` transpiles through esbuild and does **not** check types.
- **`astro build`** validates every content file against `src/content/config.ts`.
- **`scripts/check-content.mjs`** validates the relationships *between* files — a `caseStudySlug` with no case study, an image reference with no asset, a site origin that disagrees with `public/CNAME`. Neither Astro command looks at these.

## Layout

```
src/
  content/          the database — projects (.md), case-studies (.mdx), journal (.md)
    config.ts       Zod schemas; the schema authority
  lib/
    site.ts         identity + URLs — one source for name, email, profiles, origin
    content.ts      the only module that calls getCollection(); ordering, labels, links
    resume.ts       resume body (regenerated by the admin editor)
    format.ts       date and tag formatting
    admin.ts        localStorage keys for the admin surface
  layouts/          BaseLayout (public shell), CaseStudyLayout, AdminLayout
  components/       presentational only
  pages/            routes
  styles/           theme.css (tokens) -> global.css (components) -> admin.css
scripts/
  check-content.mjs cross-file content checks (`--self-test` to verify the parser)
```

## Deployment

`.github/workflows/deploy.yml` builds and publishes to GitHub Pages **on push to `main` only**.
Feature branches do not deploy. `.github/workflows/ci.yml` runs `npm run check` on pull
requests and non-`main` pushes.

The origin is written down in three places that must agree, and `npm run check` enforces it:
`public/CNAME`, the `site` fallback in `astro.config.mjs`, and `site.url` in `src/lib/site.ts`.
`SITE_URL` and `CUSTOM_DOMAIN` are optional repository Actions *variables* that override the
first two at build time.

## Authoring

- **Projects / case studies / journal** — add a file under `src/content/`. Run `npm run check`.
- **Resume** — edit `src/lib/resume.ts`, or use `/admin/resume` and commit its export over the file.
- **Identity** (name, email, GitHub, LinkedIn, origin) — `src/lib/site.ts`, nowhere else.

`/admin` is a browser-only authoring surface: the site is static, so it persists nothing and
publishes nothing. It keeps drafts in `localStorage` and exports files you commit by hand.
See `.claude/rules/admin-surface.md`.
